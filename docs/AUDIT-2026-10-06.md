# LightTrail 产品、工程与文档全面审查

> 日期：2026-10-06（本地检查跨 10 月 5–6 日）。基线：main / 4b04b81。
> 本次交付为审查、文档整合与路线图，未修改产品实现，未执行真实外部 API、发布、提交或 push。

## 1. 结论

现有单体架构、契约、工具、四条管线、记忆和前端值得保留。**工程链路比较完整，首个真实拍摄决策仍未达到可靠验收。** 最严重问题是失败数据未约束模型结论，以及天气缺失值和时效判断会制造有利条件。其次是取消导致许可泄漏、基础计算/规格接线、结果恢复和数据外传边界。

小北已确认首个验收场景“今晚火烧云是否值得去”。建议从已有收藏机位的本地单用户开始，先修真实性，再使一次决策可保存、恢复和复核，最后批准真实数据验证。完整 CaptureEvent、MCP、多智能体和公网服务保留为待评估方向，本次没有替小北采用。

三份核心文档已整合：[需求](PRD-v0.3.md)、[当前与未来能力](FEATURES.md)、[执行路线图](AGENT-ROADMAP.md)。原稿及用户未提交内容按字节保存在 [归档索引](archive/audit-20261006/INDEX.md)，不是删除历史理由。旧审查与两个 GAP 文档保留入口，指向本报告，避免继续维护相互矛盾的完成率。

## 2. 方法、范围与限制

先独立检查生产装配、API/前端主流程、核心数据计算与记忆路径，再阅读其他 AI 的发现逐项复核。当前文件清单见 [模块清单](audit/2026-10-06/module-inventory.json)：后端 83 个 Python、测试 58 个 Python、前端 31 个 TS/TSX、evals 6 个 Python。

- **系统映射覆盖全部模块**：检查入口、职责、依赖和高风险接线。核心装配、API、LLM 限流、管线、天气、曝光/天文、赶场、记忆和六页用户流程细读。
- **不是全部行、分支或所有输入均验证**：测试全量执行，但断言仅按关键缺陷抽查；契约小模块检查模型/导出；生成 TS 以重生成与哈希验证，图标/样式以结构及页面检查为主。
- 生产 API 使用 ASGI + FakeClient/失败数据替身，数值用实际工具；浏览器以现有合成 fixtures 为主。额外真实代理 UI 探查完成 M1 创建后在 D3 遇到虚拟时间测试超时，不能把该次失败认定为产品缺陷，也不能声称独立全链路 UI 通过。
- 整个审查未请求实际 LLM/天气/地图，未发送个人坐标/照片；不判断供应商当前费用、许可、可用性、竞品精度或市场唯一性。
- 历史方案与 archive 不作为有效状态审核；devlog 按近期条目和历史索引追溯，不把历史日志当作本次重验。研究附图仅作为已有证据索引，未逐图重做真实性鉴定。
- 默认 pytest 临时目录曾发生权限失败；使用项目隔离 basetemp/cache 后 458 全部通过。后续 shell 启动遇到 Windows 账户登录错误，使用现有 Node 进程与本地子进程继续，未安装系统依赖。

证据等级：**R** = 可重现运行结果；**S** = 静态接线/代码证据；**H** = 历史记录；**U** = 本次未验证。等级不等于严重度，合成成功也不等于真实用户效果。

## 4. 用户影响优先的发现

### A01 · P0 · 数据失败仍能成为高置信度出发建议（R + S）

证据：[pipelines.py](../src/lighttrail/orchestrator/pipelines.py#L230) 的 _align_card 核对请求事实，却不核对证据是否来自成功工具；_collect_async（429）将失败结果收集后继续合成。[confidence.py](../src/lighttrail/infra/confidence.py#L100) 按 Source.confidence 计分，Source 又由模型生成。

重现：所有工具返回 error，FakeClient 返回 go/high 和一条伪造 weather_forecast high 依据，实际 /api/decide 接受 go/high、degraded 为空，生成 score=85、区间 61–100。这是有意注入的错误模型输出，证明生产路径没有拒绝它，**不代表真实模型每次如此**。太阳失败的独立 D2 结构化计划端点会 needs_data，不能泛称所有入口均不降级。

影响：用户可能依据根本不存在的天气出门，UI 又称分数不是模型自评。来源种类“计算可靠”不等于此次计算成功，失败 trace 仍可沿默认 high 分类。

修复：在确定性边界校验证据的来源、成功状态、字段、地点、时间；关键缺失约束结论，模型仅解释合格事实。验收：全失败且模型坚持 go/high，API/UI 仍明确数据不足；无伪高分、无捏造来源。

### A02 · P0 · 缺失天气与错误时效制造满分机会（R + S）

证据：[weather.py](../src/lighttrail/tools/weather.py#L113) 中空云量/降雨/风速按 0 汇总；sunset_glow_score（246、328–377）缺能见度默认 50 km、缺降雨/风按 0，时效只比较日落钟点，未正确用目标日期。预报请求 timezone=auto，返回却标调用方偏移，国际位置可能错误。

重现：六天后的合成云量 50%、高云 80%，其他关键字段缺失，评分 100、置信度“高”；纽约合成空字段预报返回云量 0、降水 0、风 0，时区标 +08:00。不是气象精度校准，而是空值和时间契约缺陷。

影响：最常用的火烧云决策建立在假有利条件上。代码未实现实际云层高度、太阳光路遮挡或通勤机会成本联合判断；调研目标不能写成已有算法。

修复/验收：保留缺失值，完整度影响资格；记录获取与有效时间；按目标绝对时间判远近，冻结/过期/国际时区用例通过。现有启发式可保留为透明评分，不当作发生概率。

### A03 · P1 · 用户不能可靠继续同一次决策（R + S）

证据：[routes.py](../src/lighttrail/api/routes.py#L505) 的 decide 创建新编排上下文，没有把已存 session.history 加载进续问；[D1Page](../frontend/src/pages/D1Page.tsx) 本地保留 ID 未恢复卡与消息；[D3Page](../frontend/src/pages/D3Page.tsx) 请求空 session ID 且忽略最终 ID；[HomePage](../frontend/src/pages/HomePage.tsx) 本地最后卡未按存储时间/目标日期过期；[planUrl](../frontend/src/pages/planUrl.ts) 恢复的是选择输入。

重现：实际 API 同 session 二次询问，FakeClient 记录的消息未含上轮历史。D3不进入首页会话历史、旧卡被称“今日”、D2结果不自动恢复为静态证据；已有脱敏 JSON 冻结回放有效，不能把它叫完全无恢复能力。

修复：沿已有会话/计划契约保存实际结果与版本，稳定 ID 跨页面传递，旧结果和重查分开。验收：生成→关闭→重启→恢复原结果，续问加载历史，跨用户不能恢复；过期有提示。

### A04 · P1 · 取消会泄漏 LLM 并发许可，预算配置未完全接线（R + S）

证据：[client.py](../src/lighttrail/adapters/llm/client.py#L142) 在 await asyncio.to_thread(semaphore.acquire) 被取消后，后台线程仍可取得许可，没有对应释放。隔离重现：concurrency=1，取消排队者后释放持有者，active=0 但许可不可获得。

另：设置连接/读取超时 1/2 秒，build_client 实际仍 30/120；OpenAI SDK max_retries=2 与外层最多 3 次尝试叠加，**静态上可能最多 9 次底层尝试，未做真实请求次数实验**。SSE 取消协程不自动终止已运行 worker 内请求，页面离开缺乏统一取消，Application.close 未完整关闭所有客户端资源。

影响：用户停止后后续请求可能永久等待；等待与费用不可控。修复队列取消、总尝试/超时预算及资源关闭，不先重写 SSE 全框架。验收：连续取消、超时后下一请求完成，次数可计数，UI 区分停止等待与已取消外部请求。

### A05 · P1 · 基础参数与生产知识层存在真实缺口（R + S）

证据：[exposure.py](../src/lighttrail/tools/exposure.py#L92) 将快门 round(..., 2)；[basic.py](../src/lighttrail/tools/basic.py#L31) timezone 使用整数而非 timedelta；[composition.py](../src/lighttrail/composition.py) 生产知识提供者只构造 FTS，其 lookup_camera 返回 None，独立 catalog YAML 测试不等于生产装配。[pipelines.py](../src/lighttrail/orchestrator/pipelines.py) 的 _values_equivalent 未正确处理分数形式等价比较。

重现：1/250 秒零 EV 调整返回 0.0；1/125s 与 0.008s 判不等；+08 时间工具返回 +00；S5M2/14mm/f2.8 生产自动 NPF 为 null。常见长曝光测试通过并不能掩盖短快门缺陷。

修复/验收：数值保持必要精度，正确构造时区，接 catalog 到知识门面，按单位解析数值；生产装配验证 S5M2 与未知机型降级。site_match 将合法月照 0 通过 or 50 变 50 属另一个静态空值问题，纳入相同边界批次。

### A06 · P1 · 太阳事件部分缺失会抹掉可用日落，月相单位错误（R + S）

证据：[astronomy.py](../src/lighttrail/tools/astronomy.py#L194) 将 dawn/dusk 等事件串联，未分别处理无事件；moon_phase（365、380）把 Astral 0–27.99 的相位索引解释为 0–29.53 天月龄，并代入亮面公式。安装依赖的函数文档明确相位分段与 UTC 日期。

重现：78.2°N 极昼抛 ValueError；伦敦 51.5°N、6 月 21 日没有天文曙暮光，也导致整个 sun_times 失败，虽有日落。phase=21 注入值被算出 62% 照亮度，体现单位不匹配。tz_offset 被解析但未用于月相日期语义。

修复/验收：每个事件独立可缺失，保留可用日落，明确不存在与取数失败；校对依赖单位及本地/UTC 日期。银河近似公式未做独立星历大样本验证，不能据旧四样本声称全范围 ±0.5°。

### A07 · P1 · 本地运行不等于数据、密钥和写接口均安全（R + S）

证据：[app.py](../src/lighttrail/api/app.py#L79) CORS *，默认本地 user_id 且无认证；实际 ASGI 非本机 Origin 写事件返回 200、allow-origin=*。这是服务端边界证据，**未证明绕过具体浏览器私网防护的攻击**。地图端点额外检查不能保护全部写接口。

[config.py](../src/lighttrail/config.py#L149) 百度 AK 与 LLM Key 在 repr 中可见，假值重现成立；部分 str(exc) 异常链路仍需检查敏感过滤。档案/相关事件可进入模型上下文，照片/base64/EXIF可发送视觉模型，加载地图会外传坐标。图片工具接受本地路径的权限边界不能只依赖上传端点的临时路径；未演示越权攻击，属于静态风险。

已有控制值得保留：用户目录隔离、上传分块限额、确认 outcome 才写 D4 事件、默认导出移除结构化坐标、地图主动加载。还缺统一可理解的发送提示、删除/撤回和来源约束。修复/验收见 U2-3；公网身份方案单独确认，不把匿名 localhost 当多用户服务。

### A08 · P1（实验能力）· 赶场缺少真实行程语义与可用数据接线（R + S）

证据：[chase.py](../src/lighttrail/domain/chase.py) 把 depart_at 作为第一机位到达，且以 window_end 才离场，无法为了下一机位提前结束；API [routes.py:1050](../src/lighttrail/api/routes.py#L1050) 用名称索引机位，重名覆盖。WGS84 坐标直接发送地图适配，路由侧未像 JS 地图层完成坐标转换。

新增静态接线证据：async create_chase_plan（1040）直接调用同步 planner.plan（1078）；默认 AMap/Baidu getter 经 [http.py:129](../src/lighttrail/infra/http.py#L129) 检测到运行中的事件循环后拒绝同步取数，可能落入手工降级而非使用真实路线。未调用真实地图验证。前端 datetime-local 默认值由 toISOString 截断造成 UTC/本地偏移；最多 4 站全排列且无路段缓存带来重复外部请求风险，未测真实成本。

重现：可通过早离场完成的窗口组合被判有效拍摄时长不足。修复：稳定机位 ID、起点/出发与提前离场语义、坐标与异步边界先闭合，路由真实来源明确，再批准地图联调。不能以示意连线冒充道路几何。

### A09 · P1 · 照片点评尚不能自动回答计划为何偏离（S）

证据：[D4Page](../frontend/src/pages/D4Page.tsx) 提交 focus/plan_reference 为空；事件默认时间为确认时刻；多张处理界面保留最后成功卡，不等于逐张永久关联。点评维度/展示契约亦不完全一致，模型自由合成可导致字段缺失。

已有 EXIF 提取、用户器材读取和真实 outcome 选择已接，旧“全部悬空”的评价过重。但没有稳定计划参照、实际拍摄时间/位置选择、计划对实际比较、逐张结果回看，不能叫完整复盘闭环。新批次进行中仍有旧卡可写入风险为静态待复验项，不认定已经发生错写。

修复：先用计划 ID 和用户确认的实际结果做最小关联，清楚区分分析、暂存与写入；完整 CaptureEvent 方案待确认。验收：指定计划与照片可回看对应，用户改 outcome/时间有效，不写入上一批旧卡。

### A10 · P2 · 经验沉淀缺乏确认、撤回和可靠持久化闭环（S）

证据：[semantic.py](../src/lighttrail/memory/semantic.py) JSON 保存直接覆盖，pending 合并只保存在内存，没有相应 API/UI 用户确认入口；少量 success 便可生成“可稳定复现”式描述，无统计依据。manager 状态初始化锁已修，不应重复报为未修。

修复：原子保存和必要的并发事务、pending 持久化/确认/撤回，经验保留来源与样本量。先从最小结果记录验证用户收益，不引入向量库或自治自学习框架。验收：重启不丢 pending，确认/撤回有效，小样本不夸称稳定规律。

### A11 · P1（交付前）· 安装和支持版本承诺未被证明（S + U）

证据：[pyproject.toml](../pyproject.toml) 声明 Python >=3.10，但生产使用 asyncio.TaskGroup（3.11+），测试也用 tomllib；源树 seed 与相机 YAML 未见 wheel package_data 配置，生产根目录查找依赖 checkout。**未构建 wheel，不能声称 wheel 实测安装失败。**

前端构建通过，但 FastAPI 未提供完整生产静态发布，Vite 开发代理不能替代托管配置；VITE_API_BASE 只被部分封装消费，部分页面仍直接 /api。README旧“部署完成”与清洁安装证明不足。

修复/验收：明确支持版本、种子打包和完整安装入口；源码 checkout 与独立安装各验一次，验证 API base/同源部署。版本 0.1.0/0.2.0 差异是策略缺口，不直接认定运行故障。

### A12 · P2 · 评估分数与预留端口被误读为能力证明（S）

[evaluations judge](../evals/judge.py) 的 LocalRubric 主要数关键词、文本长度和依据条数；高分不能证明天气结论正确或经验校准。现有 [semantic.py](../evals/semantic.py) 已检查地点、日期、题材和工具参数，应保留，旧 TaskGroup “尚未使用”的结论亦不成立。

ToolContext.datasource 生产恒 None，HTTP工具绕过该端口；per-user 配置/能力矩阵可注入不等于有用户界面或任意模型可无成本配置直接切换。修复：给每条能力写生产入口与反例，不为消灭预留端口单独做大重构。新缺失数据反例必须进入评估；裁判启发式与真实质量分开报告。

## 6. GAP、FEATURES 与 MCP 提案复核

- 两份 GAP 的完成率缺少统一分母、权重与用户验收；12 项功能的数量叙述与状态表不一致。取消完成百分比，逐项现状与依赖见 FEATURES。
- 已使用 TaskGroup；相机 catalog 存在但未生产接线；档案/事件确实注入部分管线，不能说个性化全悬空。没有自动计划—实际闭环与可信学习则成立。
- 火烧云实测云层高度/光路、全局光污染、完整逐张比较、自动摘要和提醒并未因有工具/字段而实现。“本地化即不外传”不符合实际请求流。
- API TraceEvent 不是拍摄 CaptureEvent；URL 输入恢复不是结果自动保存。冻结 JSON 有价值，应准确保留。
- MCP 提案可保留作为适配方向，但“唯一 Web 入口”漏 CLI，“一天、风险极低”未经拆解测量；工具 schema 映射不解决身份、路径、取消、成本与协议兼容。
- MCP readOnly 等 annotations 不能当作来源高置信度，也不能替代身份授权。双角色或机位子代理不天然提高质量；先与单管线同输入对照，测正确性、延迟、token/成本。
- 不采纳“必须完成所有四旅程才能首次开源”的大范围门槛，也不反向擅自批准早发；本地安装、代码开放、托管服务分别准备验收，由小北决定发布阶段。
