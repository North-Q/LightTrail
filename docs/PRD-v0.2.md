> **版本**：v0.2
> **日期**：2026-08-13
> **作者**：亓孟豪

> **变更**：整合创意决策功能与记忆/可解释能力，定位从「摄影助手」升级为「拍摄决策引擎」

---

## 1. 引言

### 1.1 项目背景

大语言模型（LLM）在通用对话与推理方面已展现出强大能力，但在垂直专业领域的落地仍面临知识准确性、工具协同、场景适配等挑战。摄影是一个高度依赖专业知识（曝光三角、天文气象、构图法则）与实践经验（机位选择、时机判断）的场景。

现有摄影工具（PhotoPills、巧摄、莉景天气、Windy 等）已相当成熟，但它们本质上是**查询工具**——给你「朝霞指数 65%」「银河 3 点升起」这类**数据**，需要用户自己理解、组合并做出判断。数据的获取已经不是瓶颈，**从数据到决策的最后一公里**才是空白。

LightTrail（光迹）旨在把 LLM 的推理、工具调用与多模态能力用于摄影垂直场景，构建一个**拍摄决策引擎**：不是「查数据」，而是「给决策」——综合多源数据 + 用户个性化信息，直接回答「该不该出门、几点去、去哪拍、带什么、用什么参数」。

### 1.2 项目定位

**拍摄决策引擎**——沿「灵感 → 规划 → 决策 → 复盘」的拍摄旅程，把每个环节从「查询」升级为「决策」，并用「记忆」让决策越来越懂用户、用「可解释性」让每个决策都可信。

**核心差异化（与现有工具的对比）**：

| 维度   | 现有工具        | LightTrail         |
| ------ | --------------- | ------------------ |
| 本质   | 查数据          | 给决策             |
| 输出   | 朝霞指数 65%    | 值不值得出门       |
| 多源   | 分散在 5 个 App | 合成一个决定       |
| 个性化 | 通用参数        | 记住你的器材与偏好 |
| 反向   | 不能            | 照片 → 拍摄方案    |

**典型能力**：

- 不是「查星历表」，而是「明天凌晨适合拍银河吗？几点去、去哪拍、用什么参数」
- 不是「查朝霞指数」，而是「现在出门还来得及吗？再等 20 分钟还是放弃」
- 不是「AI 点评照片」，而是「这张怎么改进，下次同样的场景该怎么拍」
- 不是「给数据让你自己算」，而是「一句话给我完整方案」

### 1.3 项目目标

| 维度 | 目标                                                                          |
| ---- | ----------------------------------------------------------------------------- |
| 产品 | 实现决策主线四阶段的最小可用版本（MVP），覆盖风光/星空/火烧云三大题材         |
| 技术 | 构建可扩展的 Agent 框架，支持工具热插拔、多轮对话、多模态输入、记忆与可解释性 |
| 开源 | 代码开源，文档完善，可供其他开发者参考与贡献                                  |

### 1.4 文档范围

本文档定义 LightTrail v0.2（MVP）的功能需求、非功能需求与系统架构方向。不包含详细 UI/UX 设计、API 接口规范与部署运维方案（后续独立文档）。

## 2. 用户画像与使用场景

### 2.1 目标用户

**主要用户：摄影进阶爱好者**

| 特征     | 描述                                                             |
| -------- | ---------------------------------------------------------------- |
| 技术水平 | 理解曝光三角、会手动模式拍摄、有后期基础，但天文/气象知识有限    |
| 器材     | 拥有可换镜头相机（无反/单反），常用 2-3 支镜头                   |
| 题材偏好 | 风光、星空、火烧云等自然题材为主                                 |
| 痛点     | 拍前不知道去哪拍、拍时参数靠猜、临场判断靠运气、拍后缺乏专业反馈 |
| 使用习惯 | 手机随身，拍摄前 1-3 天开始规划，拍摄中需要快速决策              |

**次要用户：摄影初学者**——需要更多解释与引导，对决策的「为什么」更敏感。

### 2.2 典型使用场景

**场景一：一句话出方案（主动决策型）**

> 周三晚上，小北说：「这周末想去拍银河，有什么建议？」（未提器材——光迹记住了他的 S5M2 + 契卡 14mm）

光迹综合月相/云量/银河方位/光污染/交通，直接给出：周六条件最优、去崇明东滩、凌晨 2 点出发、用 14mm f/2.8 ISO 3200 快门 20s、备选周日晚。

**场景二：临场赌注决策（火烧云）**

> 傍晚，小北看到天边泛红，问：「现在上海，火烧云值得出去拍吗？去最近的机位要 20 分钟。」

光迹综合云量趋势 + 太阳高度 + 云层高度 + 机位距离，给出动态判断：「当前高云占比不足，爆发概率约 40%，但 20 分钟内云量还在增加，建议再等 15 分钟观察，若不转红则放弃，不必白跑。」

**场景三：照片反推方案（灵感复刻型）**

> 小北刷到一张火烧云大片，丢给光迹：「我也想要这种。」

光迹识别场景 + 光线方向 + 机位特征，反推：「这是蓝调后期处理，需西向开阔机位，等一个云量 30-50% 的傍晚，带 GND 压光比。你的 24-105mm 即可，建议傍晚 6 点前就位。」

**场景四：参数即时推荐（拍摄中辅助型）**

> 现场光线快速变化。小北问：「现在拍日落剪影，f/8、ISO 100，快门该用多少？想前景也亮一点呢？」

光迹给出初始参数，并针对「前景补亮」追加包围曝光或 GND 建议。

**场景五：照片复盘分析（拍摄后改进型）**

> 拍完回家，小北上传成片问：「这张怎么样？有什么能改进的？」

光迹多模态分析构图/曝光/色彩，并结合他的器材与拍摄记录，给出「下次同样场景该怎么拍」的可执行处方，而非泛泛点评。

## 3. 功能架构总览

LightTrail 的功能分为三层：**决策主线**（沿拍摄旅程的核心功能）、**决策地基**（贯穿全程的记忆与可解释性）、**引擎底座**（Agent 技术基础）。

```
LightTrail · 拍摄决策引擎
│
├── 决策主线（沿拍摄旅程）
│   ├── D1 灵感    ├─ 照片反推方案（图 → 方案）
│   │              └─ 一句话出方案（主动决策）
│   ├── D2 规划    ├─ 机位 × 天象匹配
│   │              ├─ 多机位赶场调度
│   │              └─ 拍摄计划编排
│   ├── D3 决策    ├─ 临场赌注决策
│   │              └─ 拍摄参数推荐（曝光三角/星空/长曝光/风光）
│   └── D4 复盘    └─ 照片智能分析（多模态）
│
├── 决策地基（贯穿全程）
│   ├── M1 个性化记忆（短期/档案/事件/语义四层）
│   └── M2 可解释性（数据透明/推理可见/建议依据/来源标注）
│
└── 引擎底座（Agent 技术）
    ├── A1 多轮对话与工具调用
    ├── A2 工具注册表
    ├── A3 模型路由（ecnu-plus / ecnu-max）
    └── A4 数据源接入（天文/气象/地图/光污染）
```

## 4. 决策主线

### 4.1 D1 — 灵感（从「想拍」到「明确方案」）

**定位**：把模糊意图或一张参考图，转化为明确的拍摄方案起点。

#### D1.1 一句话出方案（主动决策）

| 编号    | 需求               | 优先级 | 说明                                                                     |
| ------- | ------------------ | ------ | ------------------------------------------------------------------------ |
| D1.1-01 | 意图理解与方案启动 | P0     | 用户一句话（「这周拍银河」）→ 自动识别题材、触发多源数据采集与决策流程。 |
| D1.1-02 | 器材自动补全       | P0     | 用户未提器材时，从记忆档案自动读取（机身/镜头），无档案时主动询问一次。  |
| D1.1-03 | 多源数据综合       | P0     | 自动编排月相/天气/方位/光污染等工具的调用顺序，串行采集。                |
| D1.1-04 | 方案初稿生成       | P0     | 输出「去不去、哪天、几点、去哪、带什么、什么参数」的决策初稿。           |

#### D1.2 照片反推方案（图 → 方案）

| 编号    | 需求           | 优先级 | 说明                                                                        |
| ------- | -------------- | ------ | --------------------------------------------------------------------------- |
| D1.2-01 | 参考图场景识别 | P0     | 多模态识别参考图的场景类型、光线方向、机位特征、后期风格。                  |
| D1.2-02 | 拍摄条件反推   | P0     | 从画面反推拍摄时间窗口（蓝调/黄金时刻）、朝向、天气条件（云量、霞光类型）。 |
| D1.2-03 | 器材匹配建议   | P1     | 结合用户器材档案，判断「你的现有镜头能否拍出类似效果」，缺件时给替代方案。  |
| D1.2-04 | 复刻计划生成   | P1     | 生成「在哪、什么时候、怎么拍」的可执行复刻计划。                            |

### 4.2 D2 — 规划（从「方案」到「计划」）

#### D2.1 机位 × 天象匹配

| 编号    | 需求           | 优先级 | 说明                                                                  |
| ------- | -------------- | ------ | --------------------------------------------------------------------- |
| D2.1-01 | 天象方位查询   | P0     | 计算日出日落/银河中心相对拍摄点的方位角与仰角（复用 F2 天文能力）。   |
| D2.1-02 | 光污染等级查询 | P1     | 获取机位的暗空等级（Bortle 等级），评估星空拍摄可行性。               |
| D2.1-03 | 机位匹配排序   | P1     | 综合「题材朝向 × 光污染 × 可达性 × 用户常拍点」，对候选机位排序推荐。 |
| D2.1-04 | 机位知识库     | P2     | 沉淀用户标记的优质机位，形成可复用知识库（与记忆的事件层联动）。      |

| D2.2-02 | 机位间通勤估算 | P1     | 估算 A→B 机位的车程，判断是否赶得上下一窗口。                   |

## 5. 决策地基

### 5.1 M1 — 个性化记忆

**定位**：让决策「越用越懂用户」。记忆分四层：

| 层次     | 内容                         | 生命周期 | 存储             |
| -------- | ---------------------------- | -------- | ---------------- |
| 短期记忆 | 当前对话上下文               | 会话内   | 内存（已实现）   |
| 用户档案 | 器材、偏好、常拍点、技能水平 | 长期稳定 | JSON 文件        |
| 事件记忆 | 拍摄记录、经验教训、纠错反馈 | 长期增长 | JSON/SQLite      |
| 语义记忆 | 摄影知识（教材/攻略）        | 长期     | RAG 知识库（P2） |

#### M1.1 记忆写入

| 编号    | 需求                   | 优先级 | 说明                                                                             |
| ------- | ---------------------- | ------ | -------------------------------------------------------------------------------- |
| M1.1-01 | 用户档案手动配置       | P0     | 提供 profile 文件，用户填写器材/偏好/常拍点。                                    |
| M1.1-02 | 对话自动抽取（实验性） | P1     | Agent 从对话中识别「新事实」（换镜头、新偏好、纠错），自动写回档案。核心研究点。 |
| M1.1-03 | 记忆冲突与更新         | P1     | 新旧记忆冲突时（换镜头）更新而非追加；过期记忆标记。                             |

#### M1.2 记忆检索

| 编号    | 需求         | 优先级 | 说明                                                           |
| ------- | ------------ | ------ | -------------------------------------------------------------- |
| M1.2-01 | 档案常驻注入 | P0     | 用户档案精简后常驻 system prompt，保证每次对话「记得你」。     |
| M1.2-02 | 事件按需检索 | P1     | 拍摄记录按「地点/题材/时间」关键词匹配后注入，避免上下文膨胀。 |

### 5.2 M2 — 可解释性

**定位**：让每个决策「有依据、可信任」。分四层：

| 层次     | 含义                                       | 优先级 |
| -------- | ------------------------------------------ | ------ |
| 数据透明 | 展示调用了哪些工具、拿到什么数据           | P0     |
| 建议依据 | 每条结论附计算/推理依据（如 NPF 法则公式） | P0     |
| 来源标注 | 数据来源 + 置信度（哪些可信、哪些是估算）  | P1     |
| 推理可见 | thinking 思考链摘要                        | P1     |

| 编号  | 需求             | 优先级 | 说明                                                   |
| ----- | ---------------- | ------ | ------------------------------------------------------ |
| M2-01 | 工具调用轨迹     | P0     | 记录并展示本轮调用了哪些工具、关键数据。               |
| M2-02 | 建议依据生成     | P0     | 参数/决策输出时附「为什么」（公式、数据、权衡）。      |
| M2-03 | 来源与置信度标注 | P1     | 区分「天文计算（精确）」vs「火烧云概率（经验估算）」。 |
| M2-04 | 推理摘要         | P1     | 展示 thinking 的浓缩版（非原始冗长输出）。             |

## 7. 非功能需求

### 7.1 性能

| 编号  | 需求           | 说明                                           |
| ----- | -------------- | ---------------------------------------------- |
| NF-01 | 单轮响应时间   | 纯文本 ≤ 10s；1 次工具调用 ≤ 15s；多轮 ≤ 30s。 |
| NF-02 | 串行调用约束   | 同一进程内 LLM 调用严格串行。**已实现**。      |
| NF-03 | 工具执行超时   | 单个工具超时 10s，返回错误供模型重试。         |

## 11. 术语表

| 术语          | 说明                                              |
| ------------- | ------------------------------------------------- |
| 曝光三角      | 光圈、快门、ISO 共同决定曝光量                    |
| EV（曝光值）  | 场景亮度对数标度，EV = log₂(N²/t)                 |
| 500 法则      | 星空最大快门 ≈ 500 / (焦距 × 裁切系数)            |
| NPF 法则      | 更精确的星空快门法则，考虑像素间距与光圈          |
| ND 滤镜       | 中性密度滤镜，均匀减光用于长曝光                  |
| 黄金时刻      | 日出后/日落前约 1 小时                            |
| 蓝调时刻      | 日出前/日落后约 30min，天空深蓝                   |
| 天文晨光/暮光 | 太阳地平线下 18°，此后完全黑暗                    |
| 裁切系数      | 相对全画幅的焦距等效倍数                          |
| 火烧云        | 日出日落时天空红/橙色霞光，由大气散射             |
| Bortle 等级   | 暗空等级（1-9），衡量光污染程度                   |
| 高云          | 高空卷云，火烧云的必要条件（低云无霞）            |
| Thinking 模式 | ECNU 模型思考模式，`thinking: {"type":"enabled"}` |
| Tool Calling  | 模型返回结构化工具调用，应用执行后回传            |
| 记忆抽取      | 从对话中自动提取可复用事实写入长期记忆            |
| 可解释性      | 决策附依据、来源与置信度，让输出可信任            |
