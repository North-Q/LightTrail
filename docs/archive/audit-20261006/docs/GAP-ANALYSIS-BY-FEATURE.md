## 2. 功能点详述

### 2.1 一句话出方案 — 🟢

- **现在能做**：用户说「这周末拍银河」→ 规则优先识别题材 → 四管线编排天文/天气/机位工具采集数据 → 深推理综合出决策卡（去/哪天/几点/去哪/带什么/什么参数）。失败自动降级自由对话。
- **该做什么**：意图理解 + 器材自动补全 + 多源综合 + 方案初稿（PRD 灵感域）。
- **差在哪**：决策卡仍是单一 confidence 字段，未拆成「数据新鲜度/来源可靠性/规则覆盖/历史相似度」四维；这是下一项 D1-1 要做的。
- **代码**：`orchestrator/orchestrator.py:plan`、`application/router.py`、`orchestrator/pipelines.py`

### 2.2 照片反推复刻 — 🟢

- **现在能做**：上传一张参考图 → 多模态识别场景/光线方向/时段/机位特征/后期风格 → 结合用户器材给复刻计划（在哪、什么时候、怎么拍）。反推用独立系统提示词，与分析流程分离。
- **该做什么**：参考图场景识别 + 拍摄条件反推 + 器材匹配建议 + 复刻计划生成。
- **差在哪**：「缺件时给替代方案」未做显式规则，依赖模型推理；依赖档案有带坐标机位，否则降级提示。
- **代码**：`tools/photo_analysis.py:reverse_engineer_photo`、`orchestrator/orchestrator.py:run_reverse`

### 2.3 天象与机位规划 — 🟢

- **现在能做**：日出日落/晨昏蒙影/蓝调黄金窗口/月相月升月落/银心可见窗口（自研 J2000+岁差，±2°）；机位 × 天象 0-5 分排序；收藏机位 CRUD（坐标系校验、首次修改备份）；结构化 SpotPlan（到达/准备/拍摄/离场窗口 + 方向 + 焦段 + 器材 + 参数 + 风险 + 证据）；计划可导出脱敏快照、URL 恢复、冻结回放。
- **该做什么**：天象方位 + 光污染等级 + 机位匹配排序 + 机位知识库 + 机位地图展示 + 天气获取 + 拍摄条件评分 + 计划生成 + 备选方案。
- **差在哪**：光污染（Bortle）未做（数据源本期不做）；地图机位层为实验性（高德，费用/许可未独立核实，不公开部署）；「拍摄条件评分」未工具化，依赖模型；备选方案无自动规则。
- **代码**：`tools/astronomy.py`、`tools/site_match.py`、`api/routes.py:create_spot_plan`、`application/spot_planner.py`、`frontend/src/pages/SpotMap.tsx`

### 2.4 多机位赶场 — 🟡

- **现在能做**：2-4 机位确定性赶场规划，输出每段 leave_at/arrive_at/latest_leave_at/有效拍摄分钟/路线（provider/采集时间/降级原因）；地图适配层支持高德→百度→手工降级。
- **该做什么**：光线时间窗 + 机位间通勤估算 + 赶场调度建议 + 地图路线呈现。
- **差在哪**：v0.4 缩减为「直线距离 + 手工用时估算」MVP，真实通勤延后；路线地图层未接线，当前只能画「直线示意」非道路导航；属实验能力，不应误导用户当导航用。
- **代码**：`domain/chase.py:ChasePlanner`、`api/routes.py:create_chase_plan`、`adapters/maps.py`

### 2.5 火烧云临场决策 — 🟢

- **现在能做**：综合云量趋势 + 太阳高度 + 云层高度 + 能见度 + 降水 + 风速，启发式 0-100 评分 + 等级 + 五项依据 + 置信度（越临近日落越可信）；管线结合机位距离给「去/等/放弃」+ 依据。
- **该做什么**：火烧云概率评估 + 时间窗口与机会成本 + 决策输出。
- **差在哪**：启发式模型非气象学精确概率；未校准前不展示「命中率 X%」（PRD 明确禁止）；「火烧云判据工具化」低优先级待议。
- **代码**：`tools/weather.py:sunset_glow_score`、`orchestrator/pipelines.py`（live 管线）

### 2.6 曝光参数推荐 — 🟢

- **现在能做**：等效曝光三向换算（光圈/快门/ISO，+1 档 = 进光量 ×2）；星空 500/NPF 法则（NPF 按像素间距+赤纬修正，缺像素间距时查知识库 pixel_pitch 表）；ND 长曝光正反向换算（ND4~ND1000）。
- **该做什么**：等效曝光 + 星空 500/NPF + 长曝光 ND + 风光场景参数建议 + 月光补偿。
- **差在哪**：风光场景参数建议（剪影/黄金/蓝调/慢门）未做独立工具，依赖模型；月光补偿仅在 moon_phase 给影响建议，参数级补偿未工具化。
- **代码**：`tools/exposure.py`（三件套）、`domain/knowledge/catalog.py`（pixel_pitch 表）

### 2.7 照片复盘 — 🟢

- **现在能做**：上传 jpg/png（≤10MB 分块读取）→ EXIF 提取（exifread）+ 多模态画面分析 → 构图/曝光/色彩三维度评价 + 可执行处方（结合器材落在具体参数）；选中照片后、分析前显示原图预览，批量时当前照片与当前结果一一对应；预览只用浏览器 Object URL，换图释放。
- **该做什么**：照片上传与多模态理解 + EXIF 读取 + 三维分析 + 可执行处方 + 原图预览与结果对应。
- **差在哪**：计划—实际对账仅提取历史计划 params 注入上下文，未做结构化偏差对比；照片与事件的稳定引用待 CaptureEvent 闭环。
- **代码**：`api/routes.py:photos_review`、`tools/photo_analysis.py:analyze_photo`、`frontend/src/pages/D4Page.tsx`

### 2.8 个性化记忆 — 🟡

- **现在能做**：四层记忆（短期内存 / 档案 JSON / 事件 SQLite / 语义 JSON）；按 user_id 命名空间隔离（`data/users/{user_id}/memory/`），双用户不可串读；并发初始化安全（全局锁+用户级锁）；档案常驻 system prompt；事件按关键词/地点/题材检索（含坐标与天气快照）；事件仅 `/api/events` 显式确认才落库；语义记忆从事件提炼（min_samples/成功率），二次确认后注入；高频事件地点沉淀到机位档案。
- **该做什么**：档案手动配置 + 对话自动抽取 + 记忆冲突与更新 + 通勤/常驻画像 + 事件确认后记录 + 档案常驻注入 + 事件按需检索。
- **差在哪**：「从对话实时抽取新事实」未做（仅事件→语义提炼）；通勤/常驻画像字段未实现（主动提醒依赖项）；过期记忆标记未做；成果评价（出片率/满意度）未结构化。
- **代码**：`memory/manager.py`、`memory/profile.py`、`memory/events.py`、`memory/semantic.py`、`tools/memory_tool.py`

### 2.9 可解释性 — 🟢

- **现在能做**：TraceRecorder 记录工具/步骤/LLM 事件；SSE 经 TraceBridge 实时推送前端（queued→步骤→工具→卡片→done）；工具返回附依据字段（如 NPF 公式、火烧云各分量）；数据来源标注（如「Open-Meteo（免费）」）；置信度 HIGH/MEDIUM/LOW；深推理 thinking 摘要落成步骤事件；全局知识命中只记录来源不复制内容。
- **该做什么**：工具调用轨迹 + 建议依据生成 + 来源与置信度标注 + 推理摘要。
- **差在哪**：置信表达仍是单一 confidence 字段，D1-2 要拆成数据新鲜度/来源可靠性/规则覆盖/历史相似度四维（与 2.1 同一缺口）。
- **代码**：`infra/trace.py:TraceRecorder`、`api/events.py:TraceBridge`、各工具 `Confidence`

### 2.10 主动提醒服务 — ⏸

- **现在能做**：无（底座未做）。但 `search_memory` 工具已能检索历史事件（含坐标/天气快照），为复拍提醒预备了数据管道。
- **该做什么**：休息日提醒（按日程）+ 复拍机会提醒（按历史事件）+ 就近快速推荐（按当前位置），三块共享「时空上下文感知 + 短临预报评分 + 触达通道」底座。
- **差在哪**：全部延后（PRD 明确 MVP 后再实现，依赖 M1 通勤画像 + 事件记忆 + E3 记忆层就绪）；定时推送形态已砍（常驻进程，演示价值低）。
- **代码**：数据管道 `tools/memory_tool.py:SearchMemoryTool`；触发调度未做

### 2.11 拍摄闭环 CaptureEvent — ⚪

- **现在能做**：计划（SpotPlan）、执行、照片（D4 复盘）、事件（`/api/events`）是**四个独立入口**，未关联成统一事件。
- **该做什么**：一次拍摄以统一 CaptureEvent 关联计划、实际执行、照片、复盘和数据快照；用户明确确认出发/取消/出片/满意度后才写入长期记忆；展示计划与实际的偏差（时间/参数/预报 vs 现场）。
- **差在哪**：**最大缺口**。「越用越懂你」的产品差异化主张依赖此闭环——复拍提醒、经验校准、语义记忆提炼都缺数据基础。路线图位置：E1-1~E1-4（D1 之后、O1 之前）。
- **代码**：未接线；契约 `contracts/events.py` 部分预留

### 2.12 工程基座与发布就绪 — 🟡

- **现在能做**：引擎底座扎实——PydanticAI Agent + 声明式 ToolSpec 注册表（15 工具）+ 能力矩阵路由（tools/vision/deep，可注入，不写品牌）+ 单一并发配置（LLM_CONCURRENCY，ADR-004）+ 指数退避重试 + Thinking 模式 + 配额感知 + 全局知识库 FTS5 + 规则优先意图路由 + 受控 Plan-Execute + 超工具集护栏 + 跨会话恢复；458 passed + ruff + smoke 21/21 + lint-imports 3/0 + 前端 OpenAPI 生成稳定。
- **该做什么**：引擎底座（A-01~A-08）+ 性能/可靠性/可扩展/安全隐私（NF-01~NF-16）+ 公网发布（P1：隐私/安全/安装/演示/开源文档）。
- **差在哪**：NF-03 工具级超时未做；NF-01 逐 token 流式延后；**公网部署未收口**——`_local` 单用户无认证、CORS `*`、地图代理无认证、照片/EXIF/坐标外发告知待 P1；开源文档（许可证/贡献指南/架构图/隐私说明/已知限制）待补。
- **代码**：`runtime/agent.py`、`runtime/registry.py`、`llm/router.py`、`adapters/llm/client.py`、`composition.py`

## 3. 三大关键缺口

### 缺口 1：拍摄闭环（最大）

计划、执行、照片、复盘是四个独立入口，未关联成统一 CaptureEvent。**所有「越用越懂你」的个性化主张都悬空**——复拍提醒、经验校准、语义记忆提炼无数据基础。路线图下一阶段重点。

### 缺口 2：决策卡置信表达

DecisionCard 仍是单一 confidence 字段，未拆成「数据新鲜度/来源可靠性/规则覆盖/历史相似度」四维，未删除伪精确百分比。这是当前路线图的**下一项**（D1-1），D1–D3 共用，先做能减少后续返工。

### 缺口 3：公网发布就绪

`_local` 单用户无认证、CORS `*`、地图代理无认证、隐私边界（照片/EXIF/坐标外发告知）未收口。开源发布前必须完成 P1 全部。高德费用/许可未独立核实，S1-4 仅本地合成验证。
