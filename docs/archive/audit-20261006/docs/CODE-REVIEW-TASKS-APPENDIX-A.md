## 任务 T7：修复 astronomy.py 的极区健壮性与月相口径（补审发现）

**背景**：`src/lighttrail/tools/astronomy.py` 已于 2026-10-05 完成逐行补审 + 独立数值
交叉验证，详见 `docs/CODE-REVIEW-REPORT-2026-10-03.md` 附录 A。以下三项须修复。

### T7-1（🔴 必修）极昼/极夜下 `sun_times` 抛未捕获异常

**位置**：`src/lighttrail/tools/astronomy.py:215-216`（`sun.sunrise` / `sun.sunset` 调用）

**问题**：astral 在「太阳整日高于或低于地平线」时抛
`ValueError("Sun is always above the horizon on this day, at this location.")`，
当前代码未捕获。实测复现：

```python
from lighttrail.tools.astronomy import sun_times
sun_times(78.2, 15.6, "2026-06-21")   # 斯瓦尔巴极昼 → ValueError
```

`sun_times` 是日出/日落/火烧云/蓝调/黄金题材的管线采集源
（`orchestrator/pipelines.py:331-354`）以及 S1 结构化计划的数据源
（`application/spot_planner.py:203-212`），异常上抛到 `Orchestrator.plan` 的统一降级后，
用户得到的是「管线故障」而不是「当日太阳不落」的正确结果。

**修复方向**：
1. 对 `sunrise` / `sunset` / `dawn` / `dusk`（民用/航海/天文三档）分别捕获 `ValueError`，
   降级为 `None`，并在返回值中给出明确说明字段（如
   `"极昼/极夜说明": "当日太阳整日位于地平线以上（极昼），无日出日落"`）；
2. `_elevation_windows`（依赖高度角扫描，不受 astral 异常影响）照常执行——
   极昼下蓝调窗口应为空列表或按高度角如实给出，不要让整个函数失败；
3. **同步检查并同样处理**：`moon_events` 的 `moon.moonrise`/`moonset`（:476-477）、
   `galaxy_visibility` 的 `sun.dusk`/`sun.dawn`（:626-629）——极区应做同样的降级，
   返回说明而非抛异常。

**验收**：新增极区回归测试（如纬度 78.2 的极昼与极夜日期各一例），断言木有异常抛出
且返回体含降级说明；`pytest` 全绿。同时在 devlog 说明你选择降级而非报错的理由。

### T7-2（🟡）月相命名与照亮比例口径不一致

**位置**：`src/lighttrail/tools/astronomy.py:384-399`（命名分支）

**问题**：命名按「8 等分相区」（每区约 3.69 天）切分，与「上弦月 = 50% 照亮」的
通用定义不一致。按代码阈值实算：

| 代码命名边界 | phase_days | 实际照亮 |
|---|---:|---:|
| 娥眉月 → 上弦月 | 5.54 | 30.9% |
| 上弦月 → 盈凸月 | 9.23 | 69.2% |

真上弦（50% 照亮）在 phase_days≈7.38。结果：**用户问「上弦月」时拿到 69% 亮度的月亮，
而真正的 50% 月亮被命名为「娥眉月」**；同一返回体里 `月相名称` 与 `照亮比例（%）`
互相矛盾，而 `orchestrator/pipelines.py:486-493` 的 `_score()` 把「月相名称」当评分键
注入模型上下文，可能让模型基于错误名称给建议。

**修复方向**：把命名改为与 `照亮比例（%）` 自洽的口径（建议以 50% 照临界点定义上弦/下弦，
即 phase_days≈7.38 / 22.15，并明确娥眉月/残月的相区范围）；在工具 `description` 中写明
命名定义。**注意**：改动会使既有测试的期望值变化，需同步调整相关断言。

**验收**：新增测试断言「上弦月当天的照亮比例在 45%～55% 之间」；`月相名称` 与
`照亮比例（%）` 在所有相区边界上语义一致。

### T7-3（🟡）`sun_times` 冗余全天扫描

**位置**：`src/lighttrail/tools/astronomy.py:241-244`

**问题**：连续 4 次调用 `_elevation_windows`（黄金晨/暮、蓝调晨/暮），每次各扫描全天
288 个采样点；其中黄金、蓝调各扫描两遍（`[:1]` 与 `[1:2]` 取自两次独立扫描）。
合计约 1152 次 `sun.elevation` 调用。

**修复方向**：改为一次全天扫描、同时切分四类窗口（或扫描一次得到高度角序列后按两个
区间过滤），把 4 次扫描降为 1 次。

**验收**：重构后 `sun_times` 返回值与重构前逐字段一致（可写对比测试固定住输出），
`pytest` 全绿。
