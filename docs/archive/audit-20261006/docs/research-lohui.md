## 二、产品概况

**一句话定位**：面向风光摄影人的火烧云/朝晚霞专项预测小程序，输出「该不该出门、几点就位、往哪拍、带什么」的出工决策，而非原始气象数据。

| 维度 | 现状 |
| --- | --- |
| 产品形态 | 微信小程序（顶栏名 1.0 为「晚霞与火烧云预测」，2.0 截图显示为「LOHUI」），无 App |
| 获取方式 | 小程序搜索，纯免费，无需注册 |
| 版本节奏 | 1.0 已上线可用；2.0 已完成界面与算法重构，「即将上线」 |
| 核心场景 | 日落火烧云（晚霞）+ 日出朝霞，双模式独立物理模型 |
| 目标用户 | 风光摄影爱好者（标签自述：风光摄影、追晚霞、爬楼党） |
| 商业化 | 无任何付费点，纯免费 |

值得注意的是收藏行为：笔记 1 一周内收藏 43 次接近点赞 49 次，收藏/点赞比约 0.88——典型「工具型产品」特征（用户收藏备用而非点赞表态），说明需求真实存在。

## 三、功能拆解（基于官方截图与描述）

### 3.1 预测引擎与数据源

| 能力 | 官方披露 |
| --- | --- |
| 数值模型 | 默认「多模型最优综合（推荐）」，支持自由切换 ECMWF（欧洲中期）、GFS（美国国家气象局）、ICON（德国）三大全球模型；2.0 截图显示常用形态为「ECMWF+GFS 推荐融合」 |
| 真实落日方位角 | 强调一年四季落日方位偏差可达 60°，按真太阳方位角逆推夕阳光路 180 公里，监测进光通道有无低云阻断 |
| 高卷云解耦 | 将高空反射卷云（6–12km，冰晶幕布）与本地低云（0–2km）分开诊断，避免「满天高卷云被误判为阴天」 |
| 气溶胶诊断 | AOD 550nm + 米氏散射模型，预判霞色是「温润金黄 / 浓烈血橙 / 浑浊泛灰」 |
| 时间粒度 | 精确到分钟的晨昏节点推演 |

### 3.2 决策输出：从数据到「出工判断」

这是 LOHUI 最核心的产品设计。1.0 界面（截图 `note1_img0.jpg`）从上到下的信息流：

1. **窗口倒计时**：「距今火烧云窗口还有 4 小时 17 分」
2. **指标条**：日落 18:40 / 方位角 265° / 置信度 92%（极高）
3. **出工决断**：明确给出「谨慎出工」「推荐出工」等行动指令，附一句话理由（如「晚霞范围较局限，推荐近距离或顺手机位」）
4. **火烧云指数**：0–100 分大字圆环（示例 56 分）+ 星级（如「微弱晚霞（3 星可看）」）
5. **色谱推演**：预测霞光色彩基调（「淡黄微橙 + 蓝调交织」「洋红金橙 + 冷紫余晖」「暖杏金黄 + 清润晨紫」「苍白暗灰 + 铅灰色」）
6. **置信度分级**：92%（极高）/ 78%（良好）/ 58%（趋势参考）——高置信度才给出强建议

2.0 新增四宫格核心气象指标（截图 `note2_img0.jpg`）：高空卷云 52%（黄金区间）、本地中低云 28%（视线良好）、大气能见度 25.0km（空气优良）、落日廊道 82%（进光极佳），每项均带状态标签而非裸数值。

### 3.3 分钟级实战时间轴

两个版本均提供「动态云高拍摄时间轴」，2.0 定名「出工实战时刻」，覆盖完整晨昏链路并标注核心爆发期（约 14 分钟）：

```
18:06 黄金时刻（Golden Hour）→ 18:38 日落触地（Touchdown）
→ 18:46 点燃巅峰（Burn Window）→ 19:00 蓝调时刻/维纳斯带（Twilight）
```

每个节点附实战释义（如「云底点燃巅峰：阳光自地平线下反射低云，火烧云色彩达到饱和度顶点」），并直接给出就位建议（「建议 17:18 前就位」）。

### 3.4 空间态势：从单点到 50km 光路视野

- **1.0**：「周边 50km 空间霞光态势分布图」，静态展示今夜晚霞/明日朝霞的最高分方位（如「正南 45km，50 分·微弱晚霞」），可点击展开真实地图
- **2.0**：升级为「全景空间态势雷达」（截图 `note2_img3.jpg`，腾讯地图底图）：
  - 中心双圈：外层 10km 青色观测圈 + 机位中心动态染色圈（火烧状态实时变色）
  - 进光光路射线：一道射线自机位直插西向 45km「进光大门」，开闭状态可视化
  - 六大态势阵列：进光前哨、进光大门、南北两翼高云受光区、东方维纳斯带探测环
  - 标准/卫星双底图，点选任意探测点或地图任意位置即秒级刷新该点解算，可直接「确定设为机位」

## 四、信息架构分析

LOHUI 的界面实质是一个教科书式的三层决策结构：

| 层级 | 内容 | 对应用户问题 |
| --- | --- | --- |
| 结论层 | 指数 + 星级 + 色谱 + 出工决断 | 值不值得去？ |
| 行动层 | 就位时间 + 时间轴 + 器材建议 + 反向机位 | 几点到？往哪拍？带什么？ |
| 依据层 | PRO 四指标 + 模型切换 + 置信度 | 为什么？不准怎么办？ |

默认折叠依据层、结论先行，同时保留「看懂出片逻辑」的入口——专业性与低门槛并存。这与 LightTrail「不是查数据，而是给决策」的产品哲学**完全同构**。

## 五、开发者自述与技术路线（评论区一手信息）

评论区提供了两条关键的官方自述（LOHUI 本人回复）：

1. **开发动机**：「我就是用了 sunsetbot 和莉景之类的软件，都不太准确，而且不能放大或者要收费，所以打算自己慢慢研究一个。」——竞品痛点三点：不准、地图交互受限、收费。
2. **实现方式**：「获取方式：小程序直接搜索即可」，基于气象学物理原理 + 数值模型（非自有观测网络），无 AI 模型宣称，本质是**规则/物理驱动的评分引擎**叠加多模型输入。

一位做过同类安卓 App 的同行（浙江）提出的技术反馈值得记录：

- 「预测这种东西，最重要还是数据积累，顶尖模型之间会互相打架」——ECMWF/GFS/ICON 输出分歧时，「最优综合」的权重只能经验设定；
- 「精度好像还不如 sunsetbot 和国外老牌火烧云预测网站，但它们都是经验模型」——即竞品的分数本质是长期人工经验拟合，新工具短期难以超越；
- SunsetWx（国外老牌）API 一天有 5000 次免费额度，可「站在巨人肩膀上」。

LOHUI 用两个产品化手段回应模型分歧：**多模型综合为默认 + 用户可切换**，以及**置信度分级输出**（模型一致性高才给强建议）。这是聪明且诚实的处理方式。

## 七、风险与局限

1. **精度未经大样本验证**：发布仅一周，无历史回测数据公开。火烧云是小尺度强不确定现象，sunsetbot 用再分析数据统计的混淆矩阵表明「即使上限表现也远非确定」；LOHUI 尚无同类透明度（其 95% 置信度是模型一致性含义，不是统计命中率）。
2. **单一现象天花板**：只做朝晚霞，不做云海、星空、极光等，用户价值频次受限（霞光机会每周数次，其余时间无使用动机——「未来趋势展望」部分缓解但未根治）。
3. **无反馈闭环**：没有「用户实拍回收」机制，无法做地点级、季节级校准，这正是评论区同行指出的精度天花板。个人开发者靠手工积累数据，速度有限。
4. **个人开发者的可持续性**：三大模型 + AOD + 地图数据均有调用成本，「纯免费」承诺与长期数据开销存在张力；且单人维护、无主体，存在停更风险。
5. **评分的虚假精确风险**：0–100 分直观但无统计学概率含义，若用户以「95% 置信」理解命中率会产生预期落差（95% 实为模型间一致度）。
6. **微信小程序平台约束**：地图选点、后台推送、订阅消息能力均受平台限制，长时效提醒（如「明晚火烧云窗口」推送）实现难度高于 App。

## 八、对 LightTrail 的启示

### 8.1 定位层面：撞车与分野

LOHUI 与 LightTrail 在 D3「临场赌注决策」（火烧云）场景上**正面撞车**，且 LOHUI 已把「指数 → 决断 → 时间轴 → 器材 → 方位」的决策链做成完整闭环。但分野同样清晰：

| 能力 | LOHUI | LightTrail 目标 |
| --- | --- | --- |
| 现象覆盖 | 仅朝晚霞 | 火烧云 + 星空 + 银河 + 蓝调时刻等（天象谱系） |
| 决策范围 | 单机位、单时刻 | 多机位赶场调度、行程规划（D2） |
| 个性化 | 无（所有人同一建议） | M1 记忆：器材档案（S5M2 + 镜头组）、审美偏好、常拍机位 |
| 复盘闭环 | 无 | D4 照片分析 → 反哺预测校准 |
| 可解释性 | PRO 四指标单层展示 | M2：依据 + 来源 + 不确定性 + 翻车归因 |
| 灵感与规划 | 无 | D1 一句话出方案、照片反推方案 |

### 8.2 火烧云工具化的结论修订

PRD 附录 A2 中「火烧云工具化，低优先级待议」的判断需要更新为三点：

1. **自研火烧云评分引擎的必要性下降**：LOHUI 免费且决策化程度已高，重复造轮子无差异化价值；LightTrail 可将其作为竞品基线（Baseline），而非替代目标。
2. **「火烧云决策与规划集成」的必要性上升**：LOHUI 证明了「出工决策」需求真实且高频（收藏率数据），LightTrail 应做 LOHUI 做不到的部分——把火烧云窗口嵌入多机位调度、与星空/蓝调时刻联合规划（如「晚霞 + 蓝调 + 银河衔接」的一晚多目标行程）。
3. **数据接入的现实路径**：若需火烧云原始数据，优先级为：SunsetBot（免费网页可解析）→ 星图地球 API（B2B、覆盖全中国、按量计费）→ SunsetWx API（免费 5000 次/天）。自研物理模型仅在与记忆/复盘闭环结合后才产生差异化价值。

### 8.3 可直接借鉴的设计

1. **色谱推演**：用「淡黄微橙 + 蓝调交织」这类审美语言描述预期结果，而非纯数字——这恰是 LightTrail 记忆系统可以个性化的维度（用户偏好「浓烈血橙」还是「清透金黄」）。
2. **置信度分级表达**：92%（极高）/ 78%（良好）/ 58%（趋势参考）的三档人类可读表达，可作为 LightTrail `infra/confidence` 模块的输出文案参考。
3. **光路廊道模型**：沿真太阳方位角逆推 180km 检查进光通道，是把「点天气」升级为「路天气」的正确抽象，星空场景同样适用（检查银心方向的云量廊道）。
4. **高卷云与低云解耦**：分层云诊断避免误判，是所有天象预测的通用前提。
5. **就位时间倒推**：从「点燃巅峰」倒推「建议就位时刻」（含路程余量），是决策类产品应有的输出粒度。

### 8.4 需要规避的坑

1. 不要输出无回测支撑的精确百分比作为「概率」；LOHUI 的 95% 置信度实为模型一致性，LightTrail 的置信度应明确语义。
2. 不要把仪表盘做成数据堆砌（2.0 的 PRO 剖析若再扩将逼近临界点）；每项数据必须挂在具体决策上。
3. 免费 + 高数据成本不可持续；LightTrail 若集成外部数据需先核清配额与许可边界，并做缓存与降级设计。
