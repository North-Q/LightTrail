## 5. 关键缺口分析（最大的 5 个 gap）

### Gap 1：CaptureEvent 拍摄闭环（E1，最大缺口）

- **现状**：计划（SpotPlan）、执行、照片（D4 复盘）、事件（/api/events）是**四个独立入口**，未关联成统一事件。
- **影响**：「越用越懂你」没有数据基础——复拍提醒（D2.3-07）依赖的「计划 vs 实际偏差」「满意度」「失败原因」无法系统化沉淀。
- **路线图位置**：E1-1~E1-4（D1 之后、O1 之前）。
- **关键决策**：CaptureEvent 数据迁移是否兼容现有事件库（待小北拍板）。

### Gap 2：DecisionCard v2 三层契约（D1）

- **现状**：DecisionCard 已有 conclusion/evidence/confidence/verdict/time_window/locations/params/alternatives/degraded 字段，但未强制「结论 → 行动 → 证据」三层结构；置信表达仍是单一 confidence 字段。
- **影响**：D1-2 要求分开「数据新鲜度/来源可靠性/规则覆盖/历史相似度」四个维度，删除伪精确百分比；当前未分。
- **路线图位置**：D1-1~D1-4（S1 之后、E1 之前，**当前下一项**）。

### Gap 3：多机位赶场真实化（O1）

- **现状**：ChasePlanner 为实验能力，手工耗时 + 直线距离估算；路线地图层未接线。
- **影响**：D2.2-04 要求「路线服务返回可核验道路几何才画实线」，当前只能画「直线示意」。
- **路线图位置**：O1-1~O1-4（E1 之后）；高德费用/许可未独立核实。

### Gap 4：主动提醒能力族（E9）

- **现状**：底座、三块能力均未实现；E9-3 定时推送已砍。
- **影响**：「主动触达」产品差异化主张未落地，但 PRD 明确「MVP 后再实现」，属预期内延后。
- **路线图位置**：核心闭环完成后。

### Gap 5：公网部署就绪（P1）

- **现状**：`_local` 单用户无认证；CORS `*`；地图代理无认证；隐私边界（照片/EXIF/坐标外发告知）未收口。
- **影响**：开源发布前必须完成 P1-1~P1-4。
- **路线图位置**：P1（最后一批）。

## 7. 风险与建议

### 7.1 风险

1. **CaptureEvent 闭环是最大瓶颈**：当前所有「越用越懂你」的个性化主张都依赖此闭环，未做则复拍提醒、经验校准、语义记忆提炼均无数据基础。
2. **地图服务合规性**：高德费用/许可/配额/坐标外发告知未独立核实，S1-4 仅本地合成验证，不构成公网部署授权。
3. **火烧云评分未校准**：启发式模型无标注数据与校准集，PRD 明确「不展示命中率 X%」，当前遵守；但 D1-2 重构置信表达时须确保不回退。
4. **赶场为实验能力**：若用户误把手工估算当道路导航，存在误导风险；前端须明确标注「直线示意」。
5. **CORS 与认证**：本地开发 `*` + `_local` 无认证，公网部署前必须 P1 收口。

### 7.2 建议

1. **优先推进 D1-1 DecisionCard v2**：这是当前下一项，且是 D1–D3 共用契约，先做能减少后续返工。
2. **E1 CaptureEvent 紧随其后**：它是产品差异化的数据地基，越早做越早积累真实数据。
3. **地图服务在 O1 前完成合规核实**：避免赶场深化时才发现费用/许可障碍。
4. **主动提醒能力族暂缓**：PRD 明确 MVP 后再实现，当前专注核心闭环。
5. **开源发布前完成 P1 全部**：隐私/安全/安装/演示/文档收口，否则不建议公开。
