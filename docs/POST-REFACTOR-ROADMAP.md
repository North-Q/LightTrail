# LightTrail（光迹）· 后重构开发路线图（C0–C2）

> **版本**：v1.0 ｜ **日期**：2026-09-17
> **前置**：B0–B7 架构重构已完成；当前基线见 `docs/codex-longterm-goal.md`。
> **定位**：本文件只排真实能力闭环，不把工具存在、测试 Fake 或前端占位当作功能完成。每个批次开始前由小北确认；外部发布、真实推送和长期运行服务仍须单独确认。

---

## 1. 排序原则

1. 先补“用户入口 → 数据 → 决策 → 记忆/展示”的断链，再增加新能力。
2. 优先确定性、可解释、低外部依赖的改动；地图通勤、推送、UGC 等依赖外部系统的能力后置。
3. 每项必须明确降级行为、离线测试和最小真实联调；契约变更同步生成前端类型。

## 2. C0 决策闭环补齐（建议下一批）

| 任务 | 目标与交付 | 验收重点 |
|---|---|---|
| **C0-1 D1 照片反推入口** | 新增独立的 `photos/reverse` 流式入口，D1 页面把“参考图反推”和“照片复盘”分流；复用 `Orchestrator.reverse_plan`，不改变 D4 语义。 | 两入口各返回对应卡片；上传失败/模型失败诚实降级；OpenAPI、前端生成物与端到端测试同步。 |
| **C0-2 事件记忆写入策略** | 先由小北确认隐私语义，再实现显式确认的事件写入（推荐：D4 复盘完成后展示待写入摘要，用户确认才落库）。 | 无确认绝不写；确认后事件可检索、可参与语义提炼；user_id 隔离与重复写入测试。 |
| **C0-3 规划数据闭环** | 让 D2/D3 按题材选择数据：银河/星空补 `galaxy_visibility`、`moon_events`；候选真实机位进入 `match_sites` 确定性排序并进入 trace/card。 | 银河窗口不再是空占位；空机位、单源失败与无匹配均有明确降级；评分依据可在 SSE 查看。 |
| **C0-4 配额准入与降级** | 在普通管线及自由对话的 LLM 调用前接 `QuotaLedger.check/degrade`，将拒绝或降级原因写入 trace 与 `DecisionCard.degraded`。 | 水位边界、并发和 Planner/非 Planner 两条路径覆盖；不以模型品牌判断实现。 |
| **C0-5 结构化时间窗** | 在 `DecisionCard` 增加可选起止时间字段，淘汰 D3 页面从自然语言 `time_window` 取首时刻的展示解析。 | 时区、跨日、缺值与旧卡兼容测试；OpenAPI/TS 无漂移。 |

**C0 闸门**：pytest、ruff、import-linter、`npm run gen:api` 与 `npm run build` 全过；至少用一条银河规划和一张参考图做真实最小联调（事前确认 Key 配额）。

## 3. C1 决策能力增强（C0 后）

| 任务 | 范围 | 不做什么 |
|---|---|---|
| **C1-1 D2.2 赶场 MVP** | 真实机位间直线距离、用户填写/确认的手工用时、窗口冲突与“最晚离开”建议。 | 不接地图路线/实时路况。 |
| **C1-2 知识库第二案例** | 选择一个有可核验来源的结构化领域表（优先光污染/Bortle 或摄影窗口知识），以 source/version 入库并按需注入。 | 不爬取 UGC，不把经验阈值硬编码回工具。 |
| **C1-3 体验与可解释性收口** | 前端用结构化时间窗、机位匹配和降级原因展示真实信息；补会话回放与错误态。 | 不引入 token 逐字流式。 |

## 4. C2 发布准备与延后项

- **开源准备**：许可证核对、`.env.example`、贡献指南、变更日志、从零启动文档和安全检查；达到条件后再由小北决定是否发布。
- **延后**：E9 被动提醒、就近推荐、真实通勤、潮汐、UGC 机位、多用户/per-user Key、向量 RAG；E9-3 定时推送保持砍掉状态。
- **火烧云判据工具化**：仍是低优先级研究项，只有具备可核验来源与数据字段后再立项。

## 5. 当前建议

先做 **C0-1 → C0-3 → C0-4 → C0-5**。C0-2 涉及用户拍摄历史的写入与隐私语义，必须先由小北确认写入方式；其余四项不依赖外部付费服务，且直接提升演示时的“决策真实性”。
