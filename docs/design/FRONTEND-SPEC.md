# LightTrail 前端设计与交互规范

> 修订：2026-10-06。沿用已有视觉语言，当前实现与完成度见 [FEATURES](../FEATURES.md)，任务见 [路线图](../AGENT-ROADMAP.md)。原件含完整组件历史动机，已 [归档](../archive/audit-20261006/docs/design/FRONTEND-SPEC.md)。

## 1. 设计参考与职责

暗色摄影场景、暖色强调、卡片层级和语义图标继续保留。静态 [原型](delivery/lighttrail-prototype.html)为只读视觉参考，其中数据与交互不证明生产能力；原稿“经小北审核”的完整确认来源本次未找到，不据此把所有数值/后端约束认定不可调整。

不从设计稿恢复过时任务，不为填满页面在真实流程显示假天气。新端点由用户需求与契约决定，不再沿用“三页/90%需求无需后端”的旧判断。视觉调整应明确理由，普通必要纠错按已授权范围执行。

## 2. 六页与关键状态

| 页面 | 交互与验收方向 |
|---|---|
| Home | 当前/历史决策明确日期、过期与冻结；空档案引导去M1；历史结果可恢复是目标，当前有缺口 |
| D1 | 一句话方案与参考图；前置缺失先询问，等待/失败/取消/续问语义清楚 |
| D2 | 选择机位/日期/题材，结构化计划与缺失依据；地图列表同选；URL输入与实际结果恢复分开 |
| D3 | go/wait/skip等后端结构化结论；目标时间、行动、证据与缺失原因优先；参数展示不丢精度 |
| D4 | 图片预览、处理状态、处方及用户确认结果；明确对应照片/计划，分析不等于写长期记忆 |
| M1 | 档案与收藏编辑；无坐标/未知坐标系不落点；删除/确认与保存结果可理解 |

空态、加载、错误、数据不足、过期、冻结、成功、停止等待分别表达。无有效关键事实不得出现高置信度出发暗示；旧结果不能在新请求中当作新成功结果写入。

## 4. 可解释性与数据真实性

结论→行动→依据的层级保留。共享契约从OpenAPI生成；verdict和结构化工具字段直接渲染，不用正则猜。后端来源计分目前受模型写入影响，不能称“完全非模型自评”，也不强制主值/区间/概率环图。未经校准的精确概率或统计区间不展示；可展示明确的来源类别、缺失信息和规则局限。

依据应关联实际成功工具结果、地点、目标时间、采集时间与有效期。工具可靠类别不代表此调用成功。示例数据仅用于明确标注的原型/测试，真实页面错误时保留真实失败和可继续动作。

## 5. 地图、照片与计划回放

地图由用户主动加载，事先说明精确坐标的发送对象；未知坐标系不猜位置。地图失败保留机位列表，真实道路几何才称道路路线，手工估计明确标注。具体数据源历史评估见 [MAP-EVALUATION](MAP-EVALUATION.md)，费用/许可当前未重验。

照片使用临时ObjectURL预览，换图/卸载释放；分析前说明图像/EXIF可能发送模型。每张结果与照片相对应为目标，当前批量只保留最近成功卡的限制须诚实说明。写事件由用户确认实际结果，不自动 success。

URL仅保存选择输入；导出默认去除结构化经纬度，自填文本需核对。导入冻结计划不触网、不冒充实时重算。自动恢复、版本比较与稳定计划关联按路线图验收。

## 6. 响应式与可访问性

桌面保持信息分层；窄屏先行动/列表后图。交互有文字标签、键盘焦点与可理解错误，不能只用颜色区分结论；抽屉/模态可关闭，地图操作可由列表完成。真实现场模式在触摸尺寸与低亮度下需用户验证，旧截图不代替实际可访问性检查。

## 7. 工程验收

按变更运行类型/build、契约生成与相关组件/浏览器反例。真实决策资格、过期恢复、停止等待与确认写入是验收项，不以截图相似或固定百分比认定可用。完整范围见 [审查](../AUDIT-2026-10-06.md)。
