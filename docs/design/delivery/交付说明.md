## 2. 打开方式

### 方式一：双击浏览器（推荐）

直接双击 `lighttrail-prototype.html`，系统会使用默认浏览器打开。原型为单文件 SPA，无任何外部依赖（无 CDN、无远程字体、无外部图片），**断网 / 离线环境亦可正常打开**。

### 方式二：拖入浏览器

将 `lighttrail-prototype.html` 拖入 Chrome / Edge / Safari / Firefox 窗口即可。

### 浏览器要求

- 现代浏览器（Chrome 90+、Edge 90+、Firefox 88+、Safari 14+）
- 启用 JavaScript（默认开启）
- 推荐窗口宽度 ≥ 1080px 以获得最佳桌面布局；≤ 820px 自动切换移动布局

> 不需要任何服务、依赖、构建步骤；不需要 Node / Python / 任何运行时。

## 3. 页面导航说明

原型共 **6 个页面**，通过顶栏水平导航切换：

| 页面 | 入口 | 主要内容 |
|------|------|----------|
| **旅程总览** | 点击品牌 `LightTrail 光迹` 或 4 阶段入口卡片 | 今日决策速览（68% 火烧云环图）、四阶段入口、最近计划、记忆摘要、下一窗口预告 |
| **D1 灵感** | 顶栏「灵感」 | 自然语言输入框 + 参考图上传区；输出 3 个方案卡片（A 推荐 / B 备选 / C 照片反推），含依据链 |
| **D2 规划** | 顶栏「规划」 | 机位列表（含静态地图 SVG）、天象时间线（带日出/日落/蓝调/银河标记）、月相、银河可见窗口、赶场时间轴 |
| **D3 决策** ⭐ | 顶栏「决策」（默认高亮） | 三态决策（去/再等等/放弃）+ 倒计时 + 现场模式开关；概率依据、置信度（主值+区间+依据）、曝光三角联动、为什么这么判断、可折叠溯源、相似历史命中 |
| **D4 复盘** | 顶栏「复盘」 | 批量上传区、4 维度多模态分析（曝光/构图/色彩/时间）、可执行处方（按优先级分高/中/低） |
| **M1 记忆** | 顶栏右上「我的记忆」 | 器材档案、事件历史（含 EXIF 摘要）、语义偏好芯片 |

### 页面切换的两种方式

1. **顶栏主导航**：直接点击顶栏的水平步骤按钮
2. **内联跳转**：点击任意 `[data-nav="xxx"]` 元素（卡片、按钮、链接）即可切换

### 关键交互能力

- **倒计时**：D3 页距最佳窗口的倒计时自动循环重置（演示用）
- **三态决策**：点击「去 / 再等等 / 放弃」会同步更新 verdict 图标、标题、说明，并弹出 toast
- **现场模式**：D3 页右上「现场模式」开关会将三态决策切换为适合现场操作的大按钮布局
- **为什么这么判断**：桌面端点击面板展开内联 4 步推理 + 数据源；移动端（≤820px）改用底部抽屉（`#why-sheet`）呈现，避免页面被推到不可见区域
- **曝光三角联动**：拖动光圈 / 快门 / ISO 任一滑块，其余两项自动换算以保持 EV 14
- **参考图上传**：D1 / D4 上传区支持点击或拖拽（仅示意，不会真正上传）
- **解释中心**：页脚「数据与依据」按钮弹出数据源清单模态（可按 ESC 关闭）
- **移动端导航**（≤560px）：顶栏右侧操作收进抽屉；点击汉堡按钮打开右侧抽屉（含全部导航 + 我的记忆 + 设置），点遮罩或切换页面自动收起

> **WCAG 合规**：所有文本与背景组合的对比度均 ≥ 4.5:1（`--text-muted` 在 elevated bg 上 4.6:1，base 上 5.0:1）。

### 字体（系统回退栈，无外部依赖）

| 角色 | 字体栈 |
|------|--------|

| Data | `ui-monospace, "SF Mono", "Cascadia Code", "JetBrains Mono", Consolas, monospace`（数字、日期、参数） |

> 在中文系统（macOS / Windows）会自动回退到 PingFang SC / Microsoft YaHei，无需联网下载字体。

### 间距 / 圆角 / 动效

- 间距 4px 基准：`--sp-1` (4px) 至 `--sp-8` (64px)
- 圆角：`--r-sm` (6px) / `--r-md` (10px) / `--r-lg` (14px) / `--r-full` (999px)
- 动效：`--ease` (cubic-bezier(.2,0,0,1)) + `--t-fast` (150ms) / `--t-panel` (240ms) / `--t-max` (300ms)

### 关键组件

- **三态决策卡**：`.state-btn.go/wait/risk` + `.is-active` 高亮（带 inset 描边 + glow）
- **概率条**：`.prob-fill.go/amber/blue` 三色，对应 go / 等候 / 提示
- **置信度区间**：`.interval-scale` + `.interval-range` + `.interval-marker`（主值定位）
- **环图**：SVG `.ring` + `.ring-bg` + `.ring-fill`（stroke-dashoffset 动画，过渡 240ms）
- **天象带**：`.sky-band` 12 段渐变背景 + `.sky-mark` 时间标记
- **为什么这么判断**：可折叠面板使用 `grid-template-rows: 0fr → 1fr` 实现无 JS 高度过渡
- **现场模式**：`.decision-panel.field-mode` 切换三态卡为水平大按钮布局

## 6. 后续接入真实数据的方向建议

原型已具备完整的视觉与交互骨架，对接真实数据时建议按以下方向推进（按数据获取成本从低到高排序）：

### 第一阶段：天文数据（最低成本，立即可接）

- **数据源**：[Skyfield](https://rhodesmill.org/skyfield/) / [astropy](https://www.astropy.org/) / NOAA 太阳历表
- **覆盖**：日出日落、月相、银河中心位置、晨昏蒙影（蓝调/黄金时刻）
- **建议接入位点**：D2 天象时间线、月相卡片、银河可见窗口、D3 最佳窗口起止
- **实现方式**：Python 离线计算 + 缓存到 JSON / SQLite；前端通过 `fetch('/api/astro')` 拉取

### 第二阶段：气象数据（中成本）

- **数据源**：[Open-Meteo](https://open-meteo.com/)（免费）、[和风天气](https://www.qweather.com/)、[彩云天气](https://www.caiyunapp.com/)
- **覆盖**：云量、湿度、温度、风向、降水概率、能见度
- **建议接入位点**：D3 概率依据（云量/火烧云）、D2 赶场时间轴、D1 灵感生成方案依据
- **关键产品决策**：是否接入火烧云专项模型（如彩云的「短时预报」）以替代简单云量推断

### 第三阶段：地点与交通（中成本）

- **数据源**：[高德地图](https://lbs.amap.com/) / [百度地图](https://lbsyun.baidu.com/) / Google Maps（境外）
- **覆盖**：机位坐标、朝向解析（基于 POI + 卫星图）、实时路况、驾车/步行 ETA
- **建议接入位点**：D2 机位列表（评分 + 朝向）、D2 赶场时间轴、D3 到达可行性判断

### 第四阶段：多模态图像分析（高成本 / AI）

- **数据源**：CLIP / GPT-4V / 国产多模态模型（火山方舟 / 智谱 GLM-4V）
- **覆盖**：照片场景识别、构图评分、色彩直方图、曝光分析
- **建议接入位点**：D4 复盘（4 维度分析 + 可执行处方）、D1 照片反推方案
- **建议形态**：异步任务队列（用户上传 → 后台分析 → 推送结果）

### 第五阶段：个人记忆建模（高价值 / 高成本）

- **数据源**：用户事件历史 + 偏好反推（本地小模型 / 联邦学习）
- **覆盖**：相似场景命中、偏好归纳、决策校准
- **建议接入位点**：D3 相似历史命中、M1 事件历史与语义偏好、D3 置信度依据「我的记忆」

### 接入方式推荐：自研轻量 Agent + FastAPI

> ⚠️ 本节为设计阶段的早期接入设想。项目实际架构已演进为**自研轻量 Agent 框架**（ReAct 循环 + 代码化编排管线 + 四层记忆），并未采用 LangChain/LlamaIndex；缓存与持久化用 JSON/SQLite 起步。**权威架构见 [`docs/architecture.md`](../architecture.md) v2.0.1**（含克制清单：为何不引入 LangGraph/LangChain、向量库等）。以下数据接入位点建议仍有效。

考虑到原型需要 5 类异构数据 + AI 模型，且每类调用频率与延迟不同，架构采用：

```
┌─────────────┐    ┌──────────────────┐    ┌──────────────┐
│  Web 前端    │ ←→ │ FastAPI 网关       │ ←→ │ Python Agent  │
│  (本原型)    │    │  /api/astro        │    │  自研轻量框架  │
│              │    │  /api/weather      │    │  - ReAct 循环  │
│              │    │  /api/places       │    │  - 代码化管线  │
│              │    │  /api/review       │    │  - 四层记忆    │
│              │    │  /api/memory       │    │  - 配额感知    │
└─────────────┘    └──────────────────┘    └──────────────┘
                                                  ↓
                                        ┌──────────────────┐
                                        │ 外部数据源 + 模型 │
                                        │ (天文/气象/地图/AI)│
                                        └──────────────────┘
```

- **前端零改动**：本原型已用 vanilla JS 实现页面切换，所有动态数据通过 ID 绑定（如 `#countdown` / `#verdict-title` / `.prob-fill`），替换为 `fetch` 即可
- **后端**：FastAPI（异步、类型友好、自动文档）+ 自研 Agent 框架（见 architecture.md）+ JSON/SQLite（记忆与缓存，规模上来再升级）
- **渐进式接入**：建议从「天文 + 气象」开始（这两类纯 API，无 AI 成本），验证闭环后再加多模态模块

### 关键改造点（接入时需修改）

| 当前位置 | 静态值示例 | 改造为 |
|----------|-----------|--------|
| `#today-label` | `晚上 · 8月15日` | `GET /api/now → {greet, date}` |
| `#countdown` | `01:42:00` | `GET /api/countdown` 或 SSE 推送 |
| `.prob-fill` `style="width:68%"` | 内联样式 | 数据驱动渲染：`setStyle('width', value+'%')` |
| `.interval-marker` `style="left:72%"` | 内联样式 | 同上 |
| M1 事件列表 | 4 条固定 | `GET /api/events → render()` |
| D4 分析卡片 | 4 个固定分 | `GET /api/review/:batchId → render()` |
