### 1.3 审计后的核心判断

1. **不做全量架构重写。** `contracts`、`ToolSpec/ToolRegistry`、`AgentRuntime`、适配层、OpenAPI 类型生成、SSE trace、SQLite 记忆和现有离线测试都值得保留。
2. **先修生产接线，再加新功能。** 当前主要风险不是缺模块，而是 Web、CLI、评估三条入口拿到的依赖和行为不一致。
3. **先形成一次真实拍摄闭环。** 机位、日期、天象、行动建议、实际执行、照片、结果与复盘必须落到同一个 `CaptureEvent`，否则“越用越懂你”没有数据基础。
4. **评估必须验证语义正确性。** 当前黄金用例可能在地点、日期或题材错误时仍通过；高分不能证明决策正确。
5. **不展示未经校准的精确概率。** 火烧云等结果应先展示数据新鲜度、来源可靠性、规则覆盖和风险，不把经验权重包装成概率。

## 2. 产品长期主线

光迹的长期价值链只有一条：

```text
可信数据 → 摄影语义 → 可执行决策 → 现场执行记录 → 照片复盘 → 经验校准 → 更个性化的下一次决策
```

### L0：可信地基

目标：所有入口使用同一套依赖、用户命名空间、路由、知识和降级策略；评估能抓住地点、日期、题材错误。

完成标志：Web/CLI/evals 同一请求产生等价的计划语义；不存在旧路径旁路；生产装配有集成测试。

### L1：可用的单次拍摄规划

目标：用户明确选择题材、机位和日期后，得到可复现、可执行的 SpotPlan，而不是依赖自由文本猜测。

完成标志：计划包含到达、准备、拍摄、离场窗口，以及方向、焦段、器材、参数和失败预案；刷新页面或分享 JSON 后仍可还原。

### L2：可信的决策表达

目标：统一 D1–D3 的 DecisionCard，分开“结论”“行动”“证据”，对不确定性保持诚实。

完成标志：每个关键判断都能追到数据源、采集时间和有效期；没有伪精确百分比；缺数据时主动降级。

### L3：拍摄—复盘闭环

目标：一次规划、执行、照片、复盘和记忆更新由同一个 CaptureEvent 串联。

完成标志：用户能比较计划与实际，明确标记是否出发、是否出片、满意度和偏差原因；系统只在用户确认后沉淀长期记忆。

### L4：多目标赶场与差异化数据

目标：在单机位计划可靠后，再处理火烧云 → 蓝调 → 星空等多目标时空调度，并按证据逐步引入光污染、云层光路等数据。

完成标志：调度具有真实起点、交通耗时、缓冲和可提前离场语义；坐标系与路线来源透明；任何外部数据源均通过许可、成本、稳定性评审。

### L5：开源与持续学习

目标：形成可安装、可演示、可解释、隐私边界清楚的开源项目，并用真实事件做离线校准。

完成标志：全新环境可复现；个人照片/坐标默认本地存储；发布文档不夸大能力；校准指标达到预设样本门槛后才进入 UI。

## 3. 明确不做的事

在下面的触发条件出现之前，Agent 不得主动扩张范围：

- 不做微服务拆分：单体边界足够，尚无独立扩缩容需求。
- 不做多 Agent：决策流程可控且线性，先把单 Agent 和确定性管线接正确。
- 不做向量 RAG：结构化 YAML + SQLite FTS5 足够；只有召回评估证明 FTS5 不足时再提案。
- 不做社区/UGC 平台、AR 取景或交易能力：偏离核心拍摄闭环。
- 不做常驻定时推送：先验证用户是否愿意持续记录和复盘。
- 不自建“精确火烧云概率模型”：没有标注数据与校准集时，只能做透明的规则评分。
- 不抓取受平台条款或版权限制的内容；调研材料只转化为摘要、出处和产品假设。
- 不在没有统计样本时展示“命中率 83%”之类数字。

## 7. D1：DecisionCard v2 与可信表达

### D1-1 统一三层决策契约

固定为：`结论`（去/等等/放弃/信息不足）→ `行动`（何时、去哪、怎么拍）→ `证据`（数据、来源、时效、风险）。D1–D3 共用同一核心契约，场景字段用扩展模型表达。

### D1-2 重构置信表达

- 删除未经校准的精确百分比和伪区间。
- 分开显示：数据新鲜度、来源可靠性、规则覆盖度、历史相似度。
- 只有样本数和校准方法达到明确门槛后，才显示历史命中率。

### D1-3 前端决策卡统一

- 一屏先看到结论和下一步行动；证据可展开但不可缺失。
- 明确显示 `observed_at`、`valid_until`、数据源和降级原因。

### D1-4 决策一致性评估

- 校验结论与证据不矛盾；时间窗口不越界；器材参数可执行；缺关键数据时不能给强结论。

- **闸门 D1**：D1/D2/D3 至少各一个真实样例通过结构化断言和人工检查；停下汇报。

## 8. E1：CaptureEvent 拍摄闭环

### E1-1 定义事件模型与迁移

事件包含 `plan`、`execution`、`photos`、`analysis`、`decision_trace`、`memory_update`；照片只保存用户明确授权的信息或本地引用。

### E1-2 规划创建草稿事件

### E1-3 D4 记录真实结果

### E1-4 计划—实际对比与经验提炼
