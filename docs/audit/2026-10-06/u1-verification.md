# U1 数据资格与诚实表达修复验收

日期：2026-10-06。基于 main / 4b04b81 的本地未提交增量。未执行真实供应商请求、个人数据外发、提交、push 或发布。审查报告保留原始发现，本文件记录修复后的证据。

## 已核验的问题与修复

- **U1-1**：新增生产装配 ASGI 反例，修复前全工具 error + 模型 go/high 被 API 接受；综合解析失败则输出自由对话 token，没有保守卡片。修复后实际结果决定来源与资格，关键数据不足固定 wait/low/needs_data；来源内容和等级由代码从本次结果生成。模型不能自行补来源、更新时间或清除失败。综合解析失败、步数超限及复合 Planner 均不能旁路返回出发建议。
- **U1-2**：六个固定时钟反例在修复前失败：空值被汇总为零、缺天气得到 100 分、六天后仍高置信、两种跨日窗口漏样本、供应商绝对时刻未转换。修复保留 null 与合法零，缺失评分分量不加分、不重归一化；请求 GMT 预报，再按供应商偏移解析绝对时刻并转换到请求时区。获取时间、预报有效覆盖和目标事件分别核验。
- **U1-3**：D3 与共用卡展示目标日期、时区、实际获取时间、评估时间和缺失原因；无合格依据不能手动点亮“去”。倒计时只采用有效的含时区窗口，移除只有钟点时自动滚到明天的兼容逻辑。首页旧卡明确标历史结果，存储时间或刷新不延长预报有效期；不展示未经校准的置信度百分比、统计区间或“非模型自评”承诺。D2 原有冻结回放标签和 needs_data 行为保留。

沿现有 DecisionCard 增加 data_status、missing_data、evaluated_at、updated_at、valid_until、tz_offset。旧卡缺少资格字段视为未核验历史结果；历史 ConfidenceDetail 保留兼容字段，已核验卡不生成它，页面不再展示。

新鲜度 **6 小时**、远期 **72 小时** 是保守工程护栏，不是气象概率校准。卡片有效期取预报到期、新鲜度上限和目标事件的最早值；日落已过的出发判断保守降级，不由冻结预报自动推断反烧机会。缺失机位、日期语义不一致与配额拒绝维持原有边界。

## 页面验收

在项目根目录用项目虚拟环境重新导出生产 API 离线样本：

```powershell
.\.venv\Scripts\python.exe -m evals.u1_preview
cd frontend
npm run dev -- --host 127.0.0.1
```

打开 [手动离线验收页](http://127.0.0.1:5173/tests/u1.html?manual=1)。页面明确标注合成替身及固定时钟 2026-10-06 16:00 +08:00，使用独立浏览器存储前缀，不读写用户已有档案或历史。

1. 保存机身“合成相机”；新增“合成西岸”，经纬度均为 0，坐标系 WGS84，时区 +08:00，来源“离线合成”。
2. 点击“2. 今晚询问”，输入“今晚火烧云是否值得去”。默认所有数据失败，应显示数据不足、具体失败原因和目标日期，“去”不可被点亮。
3. 点击“补齐数据”，在决策页再次提交同一请求。应显示经实际工具核验的依据和获取时间；不显示置信度百分比或统计区间。
4. 点击“冻结 7 小时后查看”。首页显示历史结果、待更新；重新挂载首页或修改保存时刻不能续期。重新查询与历史回看分开。

[自动离线验收页](http://127.0.0.1:5173/tests/u1.html) 执行同一组件流程并显示 PASS；命令入口为 `npm run check:u1-ui`。页面替身使用 [生产 API 导出的样本](../../../frontend/tests/fixtures/u1-cards.json)，可由 [导出模块](../../../evals/u1_preview.py) 重生成。

## 边界与接续

本批证明失败数据不会被模型包装成可信出发建议；不证明真实火烧云预报准确率、天气供应商可用性或实际拍摄效果。获取时间不是供应商发布时间。未增加云高/光路数据源、框架、MCP 或多智能体。

复合 Planner 结果尚无完整目标证据资格，暂时保守提示单独查询临场决策；照片反推/复盘的完整事实核验不在本次文字火烧云场景验收内。旧结果持久化与续问历史属于 U3。U2 的取消许可、预算、基础计算、权限边界仍待修复。真实 API、个人坐标/照片与发布需另行确认；本批完成后停止，不执行 U2。
