## 可复现的实际错误

使用纯合成机位和内存 HTTP，通过生产 `build_application → FastAPI /api/decide → RuleIntentRouter → inspiration → 天气工具/SDK → U1 资格 → SessionManager` 执行，而非手写 API 卡。输入明确包含 ISO 日期、「日出前蓝调加日出」以及本人确认的晨间范围；没有修改生产路由或强制指定另一题材。

1. `RuleIntentRouter._subject_type` 按最长关键词取题材；「蓝调」与「日出」长度相同，蓝调在规则表中先出现，因此意图为 `inspiration/蓝调`，晨间事实未进入确定性事件选择。
2. `build_synthesis_json` 对蓝调采用日落事件。实际最终发送的完整 JSON 中，小时筛选事件为 **日落**，只留下 **2026-10-10 15:00、16:00、17:00、18:00、19:00、20:00（+08:00）**。原天气结果覆盖晨间，摘要却没有保留 05:00/06:00 样本。完整 JSON 和大小限制正常，并不意味着目标窗口正确。
3. `match_sites` 的蓝调默认事件同样是 sunset；`qualify_card` 对蓝调检查日落。Fake 模型故意返回晨间窗口及 `go/high` 后，实际保存卡仍为 **ready/go**，说明现有资格护栏无法发现这类意图事件错配。这是离线反例，不是对真实模型输出的推测或实际拍摄建议。
4. 晨间题材仍采集 `sunset_glow_score`，会额外携带晚间评分。仅调整用户措辞绕过蓝调关键词不能证明上述缺口已修复，本轮未采用该绕过方法。

完整合成证据：[输入](u4-morning-offline/local-inputs.json)、[真实 SDK 最终 HTTP body](u4-morning-offline/supplier-requests.json)、[综合 JSON](u4-morning-offline/synthesis-summary.json)、[完整 SSE](u4-morning-offline/response.sse.txt)、[原结果与完整工具快照](u4-morning-offline/original-result.json)、[重建后的原结果](u4-morning-offline/restored-result.json)、[计数汇总](u4-morning-offline/summary.json)。合成卡内的 05:25–06:30 仅用于反例，禁止用于本人出行。
